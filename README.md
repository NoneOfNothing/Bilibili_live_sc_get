# Bilibili_live_sc_get（blive_sc_get）

监听 B 站直播间的弹幕 WebSocket 通道，自动抓取 **SuperChat（醒目留言 / SC）** 并保存到本地。支持多房间同时监听、断线自动重连、重启后去重，并记录 SC 被删除（退款）的事件。

协议实现参考了以下开源项目对现行 web 端弹幕协议的梳理（本项目代码为独立实现）：

- [xfgryujk/blivedm](https://github.com/xfgryujk/blivedm) —— Python 弹幕库（WBI 签名、认证包格式参考）
- [simon300000/bilibili-live-ws](https://github.com/simon300000/bilibili-live-ws) —— Node.js 弹幕库
- [AsaChiri/DDRecorder](https://github.com/AsaChiri/DDRecorder) —— 录制工具（SC 落库思路）

## 功能

- 自动获取真实房间号（支持短号和直播间链接）
- 接入弹幕服务器：自动处理 WBI 签名、游客 buvid3、brotli 压缩报文
- 抓取 `SUPER_CHAT_MESSAGE`（含日文翻译版 `SUPER_CHAT_MESSAGE_JPN`）与删除事件 `SUPER_CHAT_MESSAGE_DELETE`
- JSONL 保存完整原始数据，CSV 保存关键字段（Excel 直接打开）
- 心跳保活 + 超时检测 + **带随机抖动的指数退避重连**（重试间隔 1 秒起、上限 30 秒；静默断网约 50 秒内被发现，短暂断网会自动恢复并输出可观测日志）；重启后自动跳过已保存的 SC
- CSV/JSONL 被占用（如 Excel 打开 CSV）时自动进入重试队列，每 5 秒补写；中途退出重启后也会恢复队列继续补写
- 房间级互斥锁：同一房间不会被多个实例重复监听，避免并发写入损坏数据
- 一个进程可同时监听多个直播间
- `--auto` 自动跟随浏览器（**实验性**）：扫描 Edge/Chrome 会话，把浏览器里打开的直播间自动加入监听（每 30 秒重扫，动态新增、不自动停止）。该实现方式存在明显局限，**日常使用推荐 GUI 启动方式手动管理房间**，详见[自动检测](#自动检测浏览器里的直播间auto)一节
- 图形界面：房间管理（添加/删除/启停）、实时标题、房间备注、历史 SC 查看 + 实时显示、**可选弹幕显示与按日落盘**、**发送弹幕与直播间专属表情包**、**点击弹幕正文复制**、翻阅历史时的新消息浮动计数、调试日志页签

## 快速开始

需要 Python 3.9+。

```bash
# 方式一：手动安装
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt      # Windows
.venv/bin/pip install -r requirements.txt          # Linux / macOS

# 监听单个房间（可粘贴直播间链接），Ctrl+C 停止
.venv\Scripts\python main.py 直播间号

# 监听多个房间、指定输出目录和日志文件
.venv\Scripts\python main.py 直播间号1 直播间号2 -o data --log-file logs/sc.log
```

Windows 下也可以直接**双击 `start_sc_get.bat`**（首次运行自动建虚拟环境装依赖；默认监听房间 1727071052，可在文件里修改，或从命令行传其他房间号）。

**多开**：复制 `start_room_模板.bat` 并重命名为 `start_room_你的房间号.bat`，把里面的「房间号」替换成实际直播间号，双击即可启动一个独立实例窗口（窗口标题带房间号），**无需拷贝整个项目文件夹**。含房间号的启动脚本已被 `.gitignore` 排除，不会提交到 git。

**自动跟随浏览器（实验性，不推荐）**：双击 `start_auto.bat`（或命令行 `python main.py --auto`），程序扫描 Edge/Chrome 当前打开的标签页，自动监听其中所有 B 站直播间。⚠️ 该功能实现方式依赖对浏览器磁盘快照的字节扫描，可靠性有限（见下文说明），**日常使用建议改用 GUI 启动方式**（`start_gui.bat`），在界面中添加/启停直播间更直观可控。技术细节见[自动检测](#自动检测浏览器里的直播间auto)一节。

### 参数说明

| 参数 | 说明 |
| --- | --- |
| `ROOM ...` | 房间号（必填，可多个，支持短号/链接） |
| `-o, --output-dir` | 数据保存目录，默认 `data` |
| `--cookie` | B 站 cookie 字符串，见下文 |
| `--duration 秒数` | 运行指定秒数后自动退出（0 表示一直运行） |
| `--log-file 路径` | 同时把日志写入文件 |
| `-v, --verbose` | 调试日志（所有消息类型、人气值等） |

## 输出格式

```
data/
  room_直播间号/
    sc_直播间号.jsonl     每日完整记录，一行一条 JSON
    sc_直播间号.csv       每日关键信息，utf-8-sig，Excel 可直接打开
    deleted_ids.json      被删除（退款）的 SC id -> 删除时间
    pending_records.jsonl 因文件被占用暂未写入的记录（补写成功后自动删除）
    .room_lock            房间互斥锁（进程退出自动释放，文件残留无害）
```

JSONL 中一条 SC 记录（`sc` 字段保留了 B 站推送的完整原始数据，含头像、勋章、背景色等）：

```json
{"type": "sc", "time_received": "2026-09-06T20:15:30", "room_id": 114514,
 "sc": {"id": 123456, "price": 30, "message": "主播加油", "start_time": ..., "end_time": ..., "user_info": {"uname": "..."}}}
```

CSV 列：`sc_id, price_cny, username, uid, message, start_time, end_time, duration_sec, received_time`。

删除事件会追加写入当天 JSONL（`"type": "delete"`）并登记进 `deleted_ids.json`；CSV 为追加式记录，不回改历史行。

写入失败自动重试：若 CSV/JSONL 被其他程序占用（如用 Excel 打开 CSV），该条记录会进入 `pending_records.jsonl`，程序每 5 秒自动补写（只补缺失的部分，不产生重复行），补写成功后该文件自动删除；程序中途退出也没关系，重启连接房间后会先恢复队列继续补写。

## 什么时候需要 cookie？

程序默认以游客身份抓取：会自动获取游客 `buvid3` 并对弹幕接口做 WBI 签名，多数情况足够。如果日志出现 `-352 / -403 / -412`（风控），需要提供**已登录**的 cookie：

1. 浏览器登录 bilibili.com，按 F12 打开开发者工具 → Network（网络）→ 刷新页面 → 任选一个请求 → Request Headers → 复制整行 `Cookie:` 的值；
2. 三选一：
   - 保存为项目根目录的 `cookie.txt`（推荐，注意该文件已被 .gitignore 排除）；
   - 设置环境变量 `BILI_COOKIE`；
   - 命令行 `--cookie "..."`。

cookie 只用于读取弹幕连接 token，请注意保管，不要泄露或提交到仓库。

**GUI 一键获取**：房间列表底部有「获取Cookie」按钮——确认后会自动从本机浏览器的 Cookie 数据库读取 bilibili.com 的 Cookie，写入 cookie.txt 并立即应用到当前会话。支持 Edge / Chrome / Brave / Vivaldi / Opera / Firefox（正在运行的浏览器优先，自动选择可用的 Cookie；带 SESSDATA 的已登录 profile 优先）。限制：
- 新版浏览器**运行时会独占锁定 Cookie 数据库**，获取时可能需要暂时完全退出对应浏览器再重试；
- 新版 Chrome/Edge 的 App-Bound 加密 Cookie（v20）暂无法解密，遇到时会明确提示；
- 若均失败，仍可按上文手动复制 Cookie。

## 应用配置文件（config.json）

项目根目录的 `config.json` 存放**应用级行为开关**（与界面设置 `data/gui_rooms.json` 无关）：

```json
{
  "allow_write_operations": false,
  "emoticon_tooltip": {
    "text": true,
    "unique": false,
    "id": false
  }
}
```

- `allow_write_operations`：**写操作总开关**（发送弹幕等会向 B 站提交数据的操作）。
  出于安全考虑**默认关闭**；程序默认只读，只有在文件中显式改为 `true` 后相关功能才会启用。修改后需**重启程序**生效。
- `emoticon_tooltip`：鼠标**悬浮表情**（表情面板里的表情、或弹幕区里的表情图）约 0.5 秒时提示哪些字段。
  可写成对象（如上）或列表 `["text", "unique", "id"]`，字段含义：
  - `text`：触发词（如 `[百岁山]`）
  - `unique`：表情唯一标识（如 `room_9527_109824`，即发送表情包弹幕时实际提交的 `msg`）
  - `id`：数字 `emoticon_id`

  **默认仅 `text`**；写空列表 `[]` 或全部 `false` 表示不显示提示。修改后需**重启程序**生效。
- 上述字段缺失、文件损坏、或写成 `"true"`（字符串）/数字等非布尔值时，一律按**默认值**处理（fail-safe；`emoticon_tooltip` 里字段名拼错也会整体回退默认）。程序启动时会在调试日志中显示写操作状态。

## 自动检测浏览器里的直播间（--auto）

> ⚠️ **该功能为实验性实现，存在固有问题，推荐改用 GUI 启动方式（`start_gui.bat`）手动管理房间。**
>
> 当前实现是直接按字节扫描 Edge/Chrome 写到磁盘的**会话快照文件**，这带来一系列不可靠因素：
>
> - 依赖浏览器把标签页快照落盘的时机，刚打开的直播间最长要等一个扫描周期（30 秒）才能被发现；
> - 仅支持 Edge / Chrome（Chromium 目录结构），Firefox 等浏览器无法识别；
> - 已关闭但仍在 24 小时快照残留中的直播间会被**误包含**；
> - 快照格式属于浏览器内部实现，随版本更新可能变化导致功能失效；
> - 扫描得到的信息只有房间号，主播名等仍需额外接口查询。
>
> 相比之下，GUI 方式通过界面直接添加/启停/排序直播间，状态与标题实时更新，无上述问题。

`start_auto.bat`（或 `python main.py --auto`）的工作方式：

1. 扫描 Edge / Chrome 的会话快照文件（`User Data\<profile>\Sessions\` 下的 `Session_*`、`Tabs_*`），URL 在其中以明文存储，直接提取 `live.bilibili.com/<房间号>`；
2. 把检测到的直播间全部加入监听；已被其他实例监听的房间自动跳过（通过房间锁探测）；
3. 运行中每 30 秒重新扫描一次：浏览器里**新开的直播间自动加入**；已加入的房间不会因关闭标签页而停止，需手动停止程序（Ctrl+C 或关闭窗口）。

注意事项：

- 刚打开的标签页可能过几秒才被浏览器写入磁盘快照，最长等一个扫描周期（30 秒）即可被拾取；
- 已关闭但仍在最近 24 小时快照中的房间可能被误包含（快照是滚动覆盖的，通常很快消失）；
- 仅支持 Edge 和 Chrome（相同的 Chromium 目录结构）；Firefox 的会话为 lz4 压缩格式，暂不支持；
- 扫描只读浏览器文件，不需要关闭或重启浏览器，也不需要管理员权限。

## 图形界面（GUI）

双击 `start_gui.bat`，或 `python main.py --gui` / `python gui.py`。

**无控制台窗口启动**：`start_gui.bat` 启动 GUI 后不会保留黑色 cmd 窗口（日志看 GUI 的「调试」页签）；首次运行需要初始化虚拟环境时会短暂显示一个进度窗口，装完自动关闭。如果连首次初始化也不想看到窗口（例如加入开机自启），用 `start_gui_silent.vbs`——完全零窗口，但要求已经运行过一次 `start_gui.bat` 完成初始化。

- **直播间页签**：
  - 顶部输入房间号、直播间链接或**主播个人空间网址**（`space.bilibili.com/<uid>`）后点「添加」；
  - 房间列表实时显示监听状态与直播标题：除每次连接/重连自动刷新外，监听过程中收到开播（LIVE）、下播（PREPARING）、改标题（ROOM_CHANGE）弹幕推送时**实时更新**；
  - **排序手动触发**：工具栏可选「手动拖动 / 按房间号 / 按主播名 / 按直播状态」后点「排序」，可勾选「直播中置顶」；启动时按上次记忆的顺序显示，不再自动排序；
  - **拖动排序**：按住行上下拖动即可调整顺序，顺序自动记忆到 `gui_rooms.json`；
  - **多选批量操作**：按住 Ctrl（或 Shift）可选中多个直播间，一次批量开启/停用监听或删除；
  - **点击跳转**：单击房间号打开直播间，单击主播名打开主播个人空间（SC 中的用户名同样可点击跳转）；
  - 列分隔条可拖动调整列宽，拖宽后可通过列表下方的横向滚动条查看被裁切的内容；
  - 选中房间即在下方查看该房间的历史 SC（从磁盘 JSONL 读取，已退款的标灰注明）：切换即**默认加载最新 100 条**，滚动条/滚轮滚到顶部时自动加载更早的一页；顶部显示「已读取共 x 条历史记录」，每页边界处有「（已读取 x 条历史记录）」分割点（x 为触发该次加载时已读数量），历史区底部有「（历史 x 条sc记录）」分割线（切换直播间时已保存的历史 SC 总数），其下方为实时到达的新 SC；价格按额度着色（50/100/500 分档），底部始终显示当前房间的**「共 x 条SC记录」**；
  - 醒目留言标题栏显示房间号、主播、**直播标题（截断显示）**、**同接**（弹幕服务器推送的实时在线人数 `ONLINE_RANK_COUNT`，监听期间实时更新；注意 `get_info` 的 online 字段与"看过人数"均非同接，故不采用）与**舰长数**；
  - SC 视图与调试日志均支持**中键快速滚动**：按一下中键进入滚动模式，移动鼠标即快速翻动，再按一下中键/单击左键退出（类似浏览器）；
  - **开播提醒**：监听中的直播间从非直播中变为开播时，播放系统提示音并闪烁任务栏图标（不弹窗）；列表中的「提醒」列显示开/关，**单击该列即可切换**，保存在配置中。程序启动时已开播的房间不提醒；
  - **房间列表正下方**可编辑**备注**（回车或失焦保存）、**开启/停用监听**（停用即断开并释放房间锁）、**删除**（从列表移除，磁盘数据保留）；窗口最底部仅保留**刷新历史**与**获取Cookie**。
- **弹幕区**：窗口最底部的「弹幕」开关开启后，在 SC 区下方实时显示**当前选中房间**的弹幕（时间 + 用户名 + 内容，每轮轮询批量渲染）。窗口最大化时弹幕区挤占 SC 空间；窗口化时窗口自动向下扩展、关闭时还原。弹幕按日写入 `room_<房间号>/dm_YYYYMMDD.jsonl`（仅开关开启期间的选中房间落盘；内容含用户昵称，注意隐私）。弹幕列表下方提供**发送弹幕**与**发送表情包**（见下）。
  - **点击弹幕**：单击**用户名**跳转其个人空间；单击**正文文字**把该条弹幕文本复制到剪贴板，并在发送区下方短暂显示「已复制：…」（点时间、用户名或正文右侧的空白处都不会触发复制）；**右键**「回复该弹幕 / @ 该用户」。
  - **新消息提示**：向上翻阅历史（滚动条不在最底部）时，SC 区/弹幕区**右下角会出现可点击徽标**「N 条新SC ↓」「N 条新弹幕 ↓」，点击即回到底部并恢复自动跟随；手动滚回底部后计数自动清零。SC 区行为一致。
  - **弹幕表情图**：整条都是表情的弹幕（大表情/粉丝团表情）默认显示为**表情图片**（约一行半文字高、保持比例）；弹幕开关旁的「**表情图**」勾选框可关闭（关闭后显示 `[触发词]` 文本，省流量与内存），开关状态保存在 `data/gui_rooms.json`。图片未下载好时先显示 `[触发词]` 文本、就绪后**就地替换**为图片；嵌图后仍可点击复制、右键回复；**落盘文件里始终是 `[触发词]` 文本**（`dm_YYYYMMDD.jsonl` 格式不变）。
  - **悬浮提示**：鼠标在**表情面板**或**弹幕区表情图**上停留约 0.5 秒，弹出不抢焦点的小提示（鼠标移开、换页、切房、退出即消失）；提示内容由 `config.json` 的 `emoticon_tooltip` 决定，**默认仅触发词**，可另外显示 `unique`（唯一标识）与数字 `id`。
- **发送弹幕 / 表情包（写操作，默认关闭）**：需先把项目根目录 `config.json` 的 `allow_write_operations` 改为 `true`（默认 `false`，见上文「应用配置文件」），并通过「获取Cookie」取得**已登录**的 B 站 Cookie（须含 `bili_jct`），二者都满足后输入行与「表情」按钮才可用。满足后在弹幕区底部输入内容，回车或点「发送」即可发到当前选中房间；可先选择弹幕**颜色**与**展示模式**（滚动/顶部/底部）；候选会随所选直播间刷新为**服务端实际可用项**（账号只支持 1 项时下拉就只有 1 项，属正常），仅查询失败时才回退为内置候选。点「表情」按钮在**发送行上方展开当前直播间的专属表情面板**（再点一次、「收起」或 Esc 收起，切换直播间自动收起，不另开窗口）：**按表情包分页（一页 = 一个表情包）**，可「◀ 上一包 / 下一包 ▶」或从下拉框直接跳页；表情**固定一行展示、面板高度恒定**（约 155px，不随表情数量变化），一页表情放不下时**横向滚动**（横向滚动条常显，滚轮也可横向翻动）；**点击表情即发送**（与网页端一致，不弹确认框；面板发送后保持展开，可连续挑选；**按直播间分别记住浏览到的表情包**（翻页即写入 `data/gui_rooms.json`，面板开着直接退出程序也不会丢，重启后仍生效），再次展开即回到该包；**每次展开都会刷新可用表情包**（同一房间 30 秒冷却），粉丝灯牌升级等新解锁的表情包下次展开即可同步，且会停在你原本浏览的那个包；表情图片按**原始大小 1:1** 显示（不做缩放，像素清晰；仅超过 260×72 的异常大图才会等比缩小）；异步加载并缓存，格式不受支持时回退为「[触发词]」按钮）。为避免误触与风控：同一房间 2 秒内不能重复发送、短时间内相同内容会被拦截、**文字弹幕**发送前会弹窗二次确认（表情包点击即发，不弹确认框）；失败按 B 站返回码提示（未登录 / csrf 校验失败 / 超长 / 频率过快 / 风控等）。程序**不会自动发送、不会自动重试**。
- **调试页签**：程序运行日志，每条日志带 `Room[房间号]` 前缀，可区分不同房间（如"已接入（房间号）直播间""收到 SC（房间 xxx）"），勾选后显示 DEBUG 级别（含所有弹幕消息类型与人气值）。
- 房间列表、备注、启停状态、排序/音效等界面偏好、**弹幕表情图开关**（`ui.dm_emoticon_image`），以及**每个直播间上次浏览的表情包**，都保存在 `data/gui_rooms.json`（表情包记忆在 `emoticon` 段，形如 `{"1": {"index": 1, "name": "房间专属"}}`）。
- GUI 与命令行实例共用房间锁：同一房间同一时间只会被一处监听，重复启动会显示"被占用"。

## 原理简述

1. `room/v1/Room/get_info` 把短号换算成真实房间号；
2. `xlive/web-room/v1/index/getDanmuInfo`（带 WBI 签名和 buvid3 cookie）取弹幕服务器列表和 token；
3. 连接 `wss://<host>:<wss_port>/sub`，发送认证包 `{"uid":0,"roomid":...,"protover":3,"platform":"web","type":2,"key":token,"buvid":...}`；
4. 每 20 秒发一次心跳，并以 5 秒为周期检查应答；普通消息（op=5）为 brotli 压缩的 JSON 流，其中 `cmd=SUPER_CHAT_MESSAGE` 即 SC；
5. 心跳超时（45 秒无应答）/ 连接断开后自动重连，重连前重新获取 token；等待时间按指数退避并叠加 ±30% 随机抖动（1 秒起、30 秒封顶），握手成功后重置。

## 多开说明

- 监听多个房间**不需要多开**：单实例原生支持 `python main.py 房间1 房间2 房间3`，这是推荐方式。
- 不同房间可以多开多个实例，共用 `data` 目录也安全（数据按 `room_<房间号>/` 目录天然隔离）；想更清晰也可以各用 `-o` 指定不同目录。
- **同一个房间同一时间只允许一个实例监听**：解析出真实房间号后程序会在 `room_<房间号>/.room_lock` 上加互斥锁，第二个实例会报错并停止该房间，避免并发写同一批文件导致记录重复、损坏。锁随进程退出（含崩溃）由操作系统自动释放，不存在残留死锁；磁盘上留下的 `.room_lock` 文件是正常的持有者信息记录，删不删都不影响下次启动。
- **无需拷贝项目文件夹**：单目录即可多开——代码与虚拟环境只读共享，数据按 `room_<房间号>/` 目录隔离。复制 `start_room_模板.bat` 制作双击启动脚本（含房间号的脚本不入库），或在命令行执行 `start "实例名" run_with_venv.bat 房间号`。
